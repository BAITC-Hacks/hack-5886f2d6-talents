# Данные для будущего интерфейса

В этой папке пока находится только готовый статический набор данных. Исходников интерфейса, package.json и команды npm run dev ещё нет; их добавит Савелий.

Для интерфейса используется `public/data/` и следующие URL:

| URL | Назначение |
|---|---|
| /data/graph.json | Граф, роли, топ, кластеры, объяснения и ограничения |
| /data/nodes_roles.csv | Скачивание всех ролей |
| /data/clusters.csv | Скачивание сводки кластеров |
| /data/top_nodes.csv | Скачивание приоритетов |
| /data/validation.json | Отчёт проверки входных данных |
| /data/run_manifest.json | Версия C++, конфигурация и хэши этого комплекта |

`input.json` и `result.json` рядом сохраняют происхождение значений и позволяют проверить комплект после передачи. Интерфейсу достаточно первых четырёх URL. Строковые gid нельзя преобразовывать в JavaScript Number. `meta.is_demo=false` обозначает настоящий полный прогон через C++; все роли остаются гипотезами.

Пересоздать и проверить данные из корня репозитория после сборки C++:

```powershell
python prepare_ui_data.py
```

Другой каталог или сборка: `python prepare_ui_data.py --out web/public/data --core engine/build/Release/engine.exe`. Демонстрационный fallback не используется.

Проверить уже переданные файлы, ничего не пересчитывая:

```powershell
python verify_outputs.py
```

Проверка включает все обязательные файлы, в том числе validation.json, хэши, согласованность CSV/graph/result, топ, дополнительные поля и внутренние суммы кластеров. Для сверки с локальными исходниками и бинарником добавить `--data "TechTask/data(1)/data" --core engine/build/engine.exe`.

До появления интерфейса можно проверить доступность файлов через стандартный сервер Python. Это только проверка статических URL, не экран аналитика:

```powershell
python -m http.server 8000 --bind 127.0.0.1 --directory frontend/public
# В другом терминале из корня репозитория:
python verify_outputs.py --base-url http://127.0.0.1:8000/data
```

После создания Vite-проекта в этой папке существующий public/data можно использовать напрямую. Савелию остаётся добавить реальную команду запуска интерфейса в корневой README и проверить сценарии из team/DEMO_CASES.md. Успешная выдача файлов сама по себе не проверяет поиск, граф или карточки UI.
