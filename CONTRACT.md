# Контракт обмена v1

Статус: предложение для согласования с Артуром и Савелием. Подтверждение команды пока не получено. Примеры `examples/input.json`, `examples/result.json`, `examples/graph.json` синтетические и предназначены для независимой разработки.

## Запуск ядра

Python вызывает без shell: `core --input <absolute/input.json> --output <absolute/result.json>`.
Код завершения 0 означает успех. Ядро пишет UTF-8 JSON и возвращает ровно один результат для каждого входного gid, включая изолированные узлы. Пути могут содержать пробелы. Диагностика — stdout/stderr. Python проверяет результат до экспорта; устаревший result.json не используется. Таймаут входит в общий бюджет 300 секунд.

## Общие типы

- `schema_version`: строка `1.0` во всех JSON.
- `gid`, `src`, `dst`, элементы `top_gids`: непустые строки. Нельзя преобразовывать их в float или JavaScript Number.
- `cluster_id`: целое число >= 0. Номера упорядочены по минимальному строковому gid сообщества; при изменении графа могут измениться.
- Деньги: JSON number в KZT; вычисления проверяются с абсолютным допуском 0.01 KZT и без относительного допуска.
- Все числа конечные. Неопределённые отношения — `null`, никогда NaN/Infinity.
- Роли: `consolidator`, `transit`, `distributor`, `terminal`, `coordinator`, `peripheral`.
- `role_score`, `priority_score`: числа в [0,1]. Это эвристические оценки, не вероятность виновности и не калиброванная вероятность роли.
- `evidence`: непустой человекочитаемый текст до 200 символов. `why`: непустое обоснование приоритета, отдельное от объяснения роли.

## input.json — Артуру

Корень: `schema_version`, `meta`, `nodes`, `edges`. Узел: `gid`, `depth`, `is_seed`, `cluster_id`, `metrics`, `flags`.

`metrics` сохраняет имена стартера: `in_deg`, `out_deg`, `in_kzt`, `out_kzt`, `in_tx`, `out_tx`, `pagerank`, `pass_through`. Дополнительно: `seed_in_neighbors` (прямые плательщики-seed), `neighbor_clusters` (число сообществ соседей), `turnover_kzt` (вход+выход; не уникальный оборот графа).

`pass_through = out_kzt / in_kzt` при положительном входе; иначе `null`. У seed отношение посчитано по наблюдениям, но непригодно для вывода о полном балансе.

`flags`: `isolated`, `boundary_depth` (depth=4), `truncated_by_depth` (depth=4 и out_deg=0, как в стартере), `seed_inflow_incomplete`, `pass_through_reliable` (положительный вход, не seed, не depth=4). Последний флаг означает лишь отсутствие двух известных ограничений, не полноту всех банковских потоков.

Направленное ребро: `src`, `dst`, `sum_kzt`, `n_tx`, `depth`. Одно ребро на упорядоченную пару. `meta` содержит ограничения выборки и настройки кластеризации.

## result.json — от Артура

Корень: `schema_version`, `engine`, `nodes`. `engine`: непустая строка с названием/версией ядра. Для каждой записи нужны `gid`, `role`, `role_score`, `priority_score`, `evidence`, `why`. Нельзя пропускать узлы, повторять gid, добавлять неизвестные gid или менять cluster_id. Кластеры принадлежат Python и в результате ядра не передаются.

При `depth=4` и отсутствии исходящих нельзя выдавать `terminal` только на основании out_deg=0. Python отклоняет такую роль. При отсутствии наблюдаемых связей допустима `peripheral` с низкой уверенностью и явным указанием нехватки данных.

## graph.json — Савелию

Корень: `schema_version`, `meta`, `nodes`, `edges`, `clusters`, `top_nodes`. Узлы сохраняют все поля input и получают поля результата ядра. Рёбра остаются направленными (`src` → `dst`). Если библиотеке нужны `source`/`target`, адаптировать имена в UI, не типы gid.

Кластер: `cluster_id`, `n_nodes`, `n_seed`, `sum_kzt_internal`, `top_gids` (массив строк, до 5 лидеров по приоритету), `hypothesis`. Внутренний оборот — сумма исходных направленных рёбер с обоими концами в кластере; каждое ребро учитывается один раз.

Топ: `rank`, `gid`, `role`, `priority_score`, `why`. Сортировка: priority_score по убыванию, gid лексикографически при равенстве. На полном датасете минимум 20 строк. UI должен показывать ограничения наблюдений и маркировку демонстрационного ядра из `meta.demo`, если она true.

## CSV

UTF-8, запятая, заголовок, стандартное CSV-экранирование. Ровно обязательные колонки из ТЗ. `top_gids` в clusters.csv — JSON-массив строк внутри CSV-ячейки. `gid` в CSV записан десятичной строкой без `.0`; при чтении указывать строковый тип. Метрики находятся в input.json и graph.json.

## Кластеризация

Louvain, NetworkX, seed=42, resolution=1.0. Неориентированная проекция суммирует суммы двух направлений: w({u,v})=sum_kzt(u→v)+sum_kzt(v→u). Петли исключаются только из кластеризации; в направленном графе и оборотах сохраняются. Изолированные узлы получают собственные сообщества. Входные узлы/рёбра сортируются для воспроизводимости. Версии зависимостей зафиксированы; одинаковый seed сам по себе не гарантирует одинаковый результат между версиями.

## Сообщение для команды

Артур: подтвердить CLI `--input/--output`, вложенные `metrics/flags`, поля result и шкалы 0–1. Савелий: подтвердить `nodes/edges/clusters/top_nodes`, строковые gid и отображение `flags`. Любое несовместимое изменение сначала вносится в этот файл и примеры; добавление необязательных полей допустимо в v1.
