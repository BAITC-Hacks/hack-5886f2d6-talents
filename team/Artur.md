# Артур — следующие действия по C++ и интеграции

Python адаптирован к контракту C++ Артура. Полный прогон на 2248 узлах занимает 3.39–7.88 секунды; прошли 49 тестов Python и 21 тест движка. Исходники engine/ не изменялись.

Арман получил коммит `274158f` с движком и инструкциями. Контракт `engine/CONTRACT.md` — источник истины для C++; корневой `CONTRACT.md` теперь описывает совместимый Python-экспорт и формат UI.

## Что уже готово у Армана

Проверки Parquet, сохранение всех 2248 узлов (включая 19 изолированных seed), метрики стартера, Louvain с seed=42 и суммированием встречных рёбер, три обязательных CSV, graph.json, строгая проверка результата, общий таймаут 300 секунд. Проверено 39 тестов. Python-demo проходит полный датасет за 2–4 секунды. Получено 88 сообществ, из них 8 с несколькими seed.

Полный запуск после установки зависимостей и сборки ядра: `python pipeline.py`. По умолчанию результат записывается в `out/`. Python-demo остаётся отдельным явным режимом `--demo`.

## Что Арман изменил для подключения C++

1. Вызов `engine input.json result.json`, с передачей `--config` при необходимости.
2. Плоские метрики input.json, как в твоей JSON Schema; gid остаются строками канонического int64.
3. Чтение `engine_version`, проверка совпадения cluster_id и полного набора gid.
4. Сохранение features, role_candidates, priority_breakdown, warnings и meta.config в graph.json. Правила, роли и приоритеты C++ не пересчитываются в Python.
5. Плоские узлы UI, `id=src+":"+dst` у рёбер, `meta.is_demo=false` для полного прогона C++. Сортировка при равном приоритете — по числовому gid, как у ядра.
6. Реальная сборка, тесты и прогон до CSV/graph.json, обновление README и примеров.

## Твои следующие действия

- Сохрани текущий контракт C++ стабильным на время подключения. Несовместимые изменения названий/типов полей или CLI сначала согласовать с Арманом.
- Подготовь Release-сборку и проверь `engine/tests/test_engine.py`; если у Армана возникнет проблема с локальным компилятором, передай сборку вместе с версией исходного коммита и командой сборки.
- После получения полного input.json проверь 2–3 лидера и узлы depth=4, объясни выбор роли и вклады приоритета по фактическим данным.
- Сверь с Арманом топ-20 и подтвердите, что Python сохраняет оценки без округления и повторного скоринга.
- Помоги Савелию показать `priority_breakdown`, альтернативные роли и предупреждения. `role_score` — сила признаков, не вероятность виновности.
- При изменении правил обновляй `engine/config/default.json`, тесты, README и engine_version вместе; не зашивай специальные gid.

## Приёмка совместного прогона

Все 2248 gid ровно один раз; 19 изолированных сохранены; у всех есть непустые объяснения. На границе depth=4 отсутствие исходящих не даёт terminal. Оценки 0–1, суммы и количества согласованы с рёбрами, результаты C++ и выгрузки совпадают по gid. Повторный запуск воспроизводим и укладывается в 5 минут.

Маленькие файлы `examples/` пересчитаны настоящим C++ и остаются синтетическими примерами (`meta.is_demo=true`). `engine/examples/` — канонические примеры автора ядра. На полном датасете итоговый graph.json имеет `meta.is_demo=false`.
