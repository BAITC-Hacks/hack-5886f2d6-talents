# Арман: данные и кластеры на защите

## Выступление на 60–90 секунд

«Мы взяли три исходных Parquet-файла: 2248 клиентов, 3119 направленных связей и
4840 переводов. Выборка начинается с 81 seed-клиента и идёт только по исходящим
переводам на четыре колена. Это внутрибанковские операции за июль 2026 года
от 5000 тенге, поэтому перед нами ограниченное наблюдение, а не вся финансовая
история клиентов.

На основе стартера мы проверяем идентификаторы, наличие клиентов на концах рёбер
и соответствие каждой пары суммам и количеству отдельных переводов. В граф
сначала добавляются все клиенты, в том числе 19 изолированных seed. Они получают
строку результата и собственное сообщество.

Для поиска сообществ используем Louvain. Только на этом шаге убираем направление:
вес связи равен сумме переводов в обе стороны. Случайное зерно фиксировано — 42.
На текущих данных получено 88 сообществ, в восьми есть несколько seed. Это группы
по структуре и объёмам переводов, а не доказанные преступные группы.

Внутренний оборот сообщества считаем по исходным направленным рёбрам: каждый
перевод учитывается один раз. Это оборот за период, не остаток на счетах.

Метрики и сообщества передаём в C++ для ролей и приоритетов, затем собираем
CSV и JSON для интерфейса. Все выводы — гипотезы для проверки. На четвёртом
колене отсутствие исходящих может быть концом обхода, а у seed входящие неполны.
Эти ограничения должны сопровождать объяснение приоритета».

## Короткие ответы жюри

**Почему 35 компонент, хотя стартер показывает 16?**

Это число слабосвязных компонент: связность проверяется без учёта направления.
Стартер строит граф только из концов рёбер и видит 2229 клиентов в 16 компонентах.
Мы добавляем все 2248 узлов из `nodes.parquet`: 19 изолированных seed дают ещё
19 компонент, поэтому 16 + 19 = 35. Компоненты связности и сообщества Louvain —
разные понятия; внутри одной компоненты может быть несколько сообществ.

**Почему не удаляем 97 одинаковых строк переводов?**

97 — число повторных строк сверх первых при сравнении `src`, `dst`, `date`,
`sum_kzt`. В данных нет `transaction_id`, а одинаковые отправитель, получатель,
дата и сумма могут соответствовать разным операциям. С сохранёнными строками
количество и сумма операций каждой пары сходятся с `edges.parquet`. Удаление
изменило бы подтверждённые агрегаты без основания. Мы сохраняем строки и
предупреждение о них; для решения об удалении нужны идентификаторы операций.

**Почему `gid` в JSON — строка?**

Исходный `gid` — `int64`, а идентификаторы в выборке превышают предел точного
целого JavaScript `Number` — 2⁵³ − 1. Преобразование через `float` или `Number`
может изменить ID и соединить данные не того клиента. `gid`, `src`, `dst`
передаются строками от чтения до UI; поиск выполняется по точной строке.

**Почему оборот не равен остатку денег?**

Остаток требует начального баланса и всех поступлений и списаний. Здесь есть
только наблюдаемые переводы за период, с ограничениями банка, суммы и обхода.
`turnover_kzt` узла — входящий плюс исходящий объём: эти деньги могли пройти
через несколько узлов. Разность входа и выхода также не доказывает остаток.
Отношение выхода к входу не доказывает движение именно тех же денег.

**Почему общая группа не означает преступную группу?**

Louvain выделяет сообщества по весам связей относительно структуры всего графа.
Общий контрагент или регулярные законные расчёты тоже создают сообщества.
Seed — точка начала выгрузки, не метка доказанной виновности. Корректная формулировка:
«Гипотеза: у нескольких seed есть общее сообщество переводов; проверить
контрагентов и экономический смысл операций». Общий организатор этим не установлен.
Роль и высокий приоритет тоже не являются вероятностью виновности.

**Что означает seed=42 и насколько устойчивы кластеры?**

81 seed-клиент — исходные узлы выборки; `seed=42` — независимый параметр генератора
случайности Louvain. Используем `resolution=1.0`, NetworkX 3.7 и отсортированную
вставку узлов и рёбер. Это обеспечивает повторяемость на одинаковом входе и
окружении. Устойчивость к другим зернам, порогам и новым данным отдельно здесь
не исследована; 88 сообществ — результат текущей настройки, не установленное
число реальных групп. Номера кластеров могут меняться при изменении данных.

**Как суммируются встречные переводы и внутренний оборот?**

Для Louvain `w({u,v}) = sum_kzt(u→v) + sum_kzt(v→u)`; петли исключены только из
проекции, изолированные узлы получают отдельные сообщества. Если A перевёл B
10000 тенге, а B перевёл A 5000, вес проекции — 15000. Если оба клиента в одном
сообществе, внутренний оборот также 15000, а не 30000: при экспорте каждое
исходное направленное ребро считается один раз. Суммировать вход и выход всех
членов для этого нельзя — внутренние переводы удвоятся, добавятся внешние.
Петли, если появятся, экспорт учитывает один раз; в текущей выборке их нет.

**Что изменится при миллионе узлов?**

Логика проверок и контракта сохраняется, но текущий способ хранения придётся
пересмотреть. Вместо Python-объектов NetworkX нужны компактный CSR либо
igraph/NetworKit/C++, агрегация транзакций порциями через Arrow/DuckDB и
масштабируемая реализация Louvain или Leiden. Полный JSON в памяти заменяется
порционным обменом или Arrow/Parquet. Интерфейс получает агрегаты сообществ и
загружает окрестность по запросу. При большом числе seed нужно пересмотреть
алгоритм достижимости. Срок до пяти минут на миллионе узлов требует отдельного
замера с учётом числа рёбер, операций и seed; текущий небольшой набор его не доказывает.

## Подтверждённые числа и источники

23 сентября 2026 года числа ниже пересчитаны из исходных Parquet текущими
`load`, `sanity_check`, `build_graph`, `cluster_graph` из `hackalem/data.py`.
Для этого использован Python из `.venv`, NetworkX 3.7, Louvain seed=42,
resolution=1.0. Это проверка данных и кластеризации на текущем ноутбуке;
она не означает проверку запуска на втором ноутбуке или приёмку интерфейса.

| Показатель | Значение |
|---|---:|
| Клиенты / направленные пары / переводы | 2248 / 3119 / 4840 |
| Seed / изолированные seed | 81 / 19 |
| Число узлов depth=0 / 1 / 2 / 3 / 4 | 81 / 472 / 462 / 789 / 444 |
| Слабосвязные компоненты полного графа / графа только из рёбер | 35 / 16 |
| Louvain-сообщества / сообщества минимум с двумя seed | 88 / 8 |
| Модулярность текущей проекции | 0.8588710135538153 |
| Общая сумма исходных направленных рёбер | 365890012.01 KZT |
| Сумма внутренних оборотов всех сообществ | 331254491.97 KZT |
| Повторные строки переводов сверх первых | 97 |
| Максимальное расхождение суммы пары при агрегации | около 5.82 × 10⁻¹¹ KZT |

Количество операций сходится точно, суммы проверяются с абсолютным допуском
0.01 KZT и нулевым относительным допуском. Остаток между общей и внутренней
суммой относится к переводам между сообществами. Модулярность описывает выбранное
разбиение, не точность определения ролей или подтверждение противоправной деятельности.
