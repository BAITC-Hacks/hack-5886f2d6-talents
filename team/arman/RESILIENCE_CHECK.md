23 сентября 2026. База реализации: `9598754`.

Python-часть готова: строгая проверка необязательного `meta.resilience`,
сохранение исходных значений в обеих копиях graph.meta, независимый эталон

## Независимый эталон на полном датасете

Это **результат проверки Python по входу и оценкам 1.2.0**, пока не результат
приёмки нового C++. Роли и priority по согласованному контракту 1.3.0 остаются
прежними; после получения ядра таблица должна совпасть с его результатом.

## Что покрывают новые проверки

Структура: baseline и 8 сценариев в согласованном порядке, типы без bool вместо
чисел, конечность, диапазоны, размеры и уникальность removed_gids, исходные gid.
Сохранение: удаление, появление без источника, `null`, перестановка и подмена
значений в каждой из двух graph-копий отклоняются даже с правильными SHA.
Согласованная подмена всех трёх копий обнаруживается эталоном NetworkX.

Эталон: цепь с удалением середины, звезда с удалением центра, цикл, две
компоненты, изолированный seed, петля, встречные рёбра, пустой и полностью
удалённый граф; каждое из 8 исключений независимо. Числовой порядок signed
int64 gid, неокруглённые priority, знаменатели, порядок входа и однократный
учёт связей между двумя удалёнными клиентами проверены отдельно.

Публикация: Windows-коды 5/32/33 повторяются с паузой до 50 мс; ошибки других
типов немедленно возвращаются. Один monotonic-бюджет 3 с ограничен также
deadline supervisor. Manifest последний, ошибка не выводит `complete`.
Блокирующий вызов ОС сам не прерывается: дедлайн проверяется и после возврата.
Если последний replace завершился поздно, полный комплект может уже лежать
на диске, но команда возвращает ошибку. Откат файлов не выполняется.

## Команды финальной интеграции

После получения C++ и UI собрать ядро, затем один раз пересчитать весь пакет:

```powershell
cmake --build engine/build --config Release --parallel 2
.venv/Scripts/python.exe prepare_ui_data.py
.venv/Scripts/python.exe verify_outputs.py --data 'TechTask/data(1)/data' --core engine/build/engine.exe
.venv/Scripts/python.exe -m pytest -q --basetemp out/pytest-resilience-final
.venv/Scripts/python.exe engine/tests/test_engine.py engine/build/engine.exe -v
cd frontend
npm test
npm run build
```

На этой машине системная папка pytest Temp недоступна; используется новая
`--basetemp` внутри `out`, без изменения прав. Команды проверок выполняются
с `.venv/Scripts/python.exe`. До демонстрации сохраняется рабочий порядок
остановить Vite → пересчитать → запустить из [DEMO.md](../../frontend/DEMO.md).
