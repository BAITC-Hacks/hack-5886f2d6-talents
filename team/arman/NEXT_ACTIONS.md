# Передача «Что проверить дальше» — C++ 1.2.0

Контракт из пункта 2 [FINISH_PLAN.md](../FINISH_PLAN.md) реализован в Python
и JSON Schema. Подключён коммит Артура `de1ee0a`: C++ 1.2.0 формирует действия
для всех узлов. Источник подсказок — C++; Python не пересчитывает правила.
Новый интерфейс Савелия из `0c24ee9` отображает действия; объединён в `9a2ab3e`.

## Формат, готовый для Артура и Савелия

В объект результата для каждого `gid` можно добавить `next_actions: string[]`.
Тот же объектный ключ по тому же gid сохраняется в `graph.json.nodes`.
Версия схемы остаётся `1.0`. Для старых результатов поле необязательно. Если оно
есть, допускаются 1–3 уникальные непустые строки до 200 Unicode-символов каждая;
`[]`, `null` и другие типы отклоняются. Текст и порядок сохраняются дословно.
Это уточнение контракта Артура из `de1ee0a`; оно заменяет предварительные
условия Python-коммита `5478ab9`, допускавшие пустой массив.
Колонки CSV и поля `top_nodes` остаются прежними.

Пример **фрагмента** объекта узла, синтетический gid (не отдельный result.json):

```json
{
  "gid": "100000000000000003",
  "next_actions": [
    "Запросить продолжение исходящих переводов за границей depth=4.",
    "Проверить источники наблюдаемых поступлений."
  ]
}
```

Это пример обмена на синтетическом gid, не утверждение о реальном клиенте.
Отсутствующее поле остаётся отсутствующим: Python не подставляет фиктивные действия.

## Артуру

Реализация ядра получена. Python сохраняет все списки по gid, проверяет их тип,
размер, уникальность, длину и передачу в итоговый комплект. При новых изменениях
правил обновляй engine_version и тесты; после пересчёта сохраняем весь пакет вместе.
Исходные условия и порядок действий: [передача Артура](../artur/NEXT_ACTIONS.md).

После коммита ядра совместный прогон:

```powershell
cmake --build engine/build --config Release --parallel 2
python prepare_ui_data.py
python verify_outputs.py --data "TechTask/data(1)/data" --core engine/build/engine.exe
```

Для Visual Studio путь бинарника — `engine/build/Release/engine.exe`.
`prepare_ui_data.py` находит оба варианта автоматически. Публиковать весь
`frontend/public/data` одним комплектом вместе с новым manifest.

## Савелию

Подключение выполнено в `0c24ee9`: Client/parseGraph принимают поле,
карточка показывает список «Что проверить дальше» в исходном порядке.
Источником служит `graph.nodes` по gid, не top_nodes и не CSV. Старый пакет
без поля открывается, блок скрывается; для совместимости UI также допускает `[]`,
хотя production-экспорт нового ядра требует 1–3 строки. Отсутствие действий
не означает отсутствие риска. Четыре контрольных случая указаны в отчёте.

## Что проверено в интеграции

- Старые результаты без поля принимаются; ограничения нового контракта проверяются.
- Русский текст, порядок и наличие поля сохраняются через валидацию и экспорт.
- Неверные типы, пустые строки/массив, дубли, больше трёх действий или строка
  длиннее 200 символов отклоняются в production и явном demo-режиме.
- Проверка комплекта обнаруживает потерю, изменение, перестановку и появление
  действий без источника в result.json, даже при правильных хэшах.
- Тест внешнего core worker проверяет поле на фикстуре; тест реального subprocess
  проверяет действия нового C++. Байты трёх CSV и ранжирование не меняются.

Результаты полного пересчёта и сверка четырёх контрольных gid:
[FINAL_RUN.md](FINAL_RUN.md). Синтетические подсказки в сдаваемый набор не подмешиваются.
