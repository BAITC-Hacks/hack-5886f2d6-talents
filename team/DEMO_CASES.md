# Узлы для проверки интерфейса и демонстрации

Выбраны из настоящего `out/graph.json`, рассчитанного Python ad6b1d5 и C++ 1.1.0
с настройками по умолчанию. Это примеры для объяснения модели; gid не используются
в правилах. При смене данных или настроек сверить значения с новым результатом.

| Случай | gid | Ожидаемая роль | Что проверить |
|---|---|---|---|
| Лидер топа | 100000000331309100 | coordinator | Приоритет, альтернативная роль distributor и направление потоков |
| Транзит | 100000008692291100 | transit | Вход 160000, выход 156000 KZT, отношение 0.975 |
| Граница обхода | 100000003037476100 | consolidator | depth=4, 3 отправителя, 555000 KZT, предупреждение о неполных исходящих |
| Изолированный seed | 100000000456947100 | peripheral | Поиск находит узел без рёбер; приоритет 0 не означает отсутствие риска |

## 1. Структурно связующий узел

`100000000331309100`: depth=2, не seed. Достижим из 7 seed, связан с 13 внешними
кластерами, имеет 5 отправителей и 99 получателей, всего 104 разных контрагента.
Наблюдаемый вход 984635 KZT, выход 23001375 KZT. Разница показывает неполноту
наблюдения, а не остаток на счёте.

Выполняется правило coordinator: S>=3, B>=2, D_in>=2, D_out>=2,
перцентиль объёма >=0.75. Также выполняется distributor; основная роль выбрана
по документированному порядку правил. Приоритет около 0.99982 складывается из
0.35 за охват seed, 0.15 за кластеры, 0.30 за объём и 0.19982 за контрагентов.

Фраза на защите: «Этот узел приоритетен для проверки из-за сочетания нескольких
структурных признаков. Координирующая роль — гипотеза, а не установленный факт».

## 2. Возможный транзит

`100000008692291100`: depth=3, не seed, по 3 отправителя и получателя.
Вход 160000 KZT, выход 156000 KZT; отношение 0.975 попадает в интервал 0.8–1.2.
Сила признаков около 0.88008, приоритет около 0.84399.

Правило консолидации не срабатывает, поскольку отправителей не больше получателей;
распределение требует минимум 5 получателей. Для coordinator требуется перцентиль
объёма >=0.75; у узла около 0.68551. Поэтому основной ролью становится transit.

Фраза на защите: «Объёмы входящих и исходящих близки, поэтому видим признаки
транзита. Без временного сопоставления это не доказывает движение тех же денег».

## 3. Сборщик на границе

`100000003037476100`: depth=4, 3 отправителя, вход 555000 KZT, видимых исходящих 0.
Есть наблюдаемые признаки консолидации. Ядро не назначает terminal, потому что
дальнейшие исходящие не собраны. Сила признаков снижена коэффициентом границы 0.8
и составляет около 0.69014; приоритет около 0.84069.

Фраза на защите: «Этот клиент собирает входящие от нескольких участников, но
на четвёртом колене заканчивается наблюдение. Следующий запрос аналитику —
получить исходящие переводы, чтобы проверить дальнейшую роль».

## 4. Запасной случай для поиска

`100000000456947100`: seed, depth=0, видимых рёбер нет. Он сохранён среди всех
2248 узлов, имеет peripheral и нулевой приоритет по наблюдаемому графу.
Карточка должна показывать отсутствие связей и неполноту входящих seed.

Фраза на защите: «Отсутствие связей в этой выгрузке не доказывает отсутствие
активности. Клиент не потерян при обработке и может проверяться по другим данным».
