# Артур — шпаргалка для защиты C++-ядра

Материал для возможного Demo Day 29 сентября. До завершения разработки
приоритеты определяет [план технической сдачи](../../docs/archive/team/TECHNICAL_REVIEW.md).

Сверено с полным `out/graph.json`: Python `ad6b1d5`, C++ 1.1.0,
настройки по умолчанию. Интеграция опубликована коммитом `c7f7bb4`.
Числа ниже округлены только для выступления; расчёт и сортировка используют
полные значения. После смены данных или конфигурации сверить примеры заново.

## Речь примерно на 90 секунд

> Я отвечал за аналитическое ядро на C++17. Python передаёт ему направленный
> граф, базовые метрики и кластеры. Ядро добавляет достижимость из разных seed
> и связи между кластерами, затем назначает роль и приоритет проверки.
>
> Результат можно объяснить через числа. Первый клиент достижим из семи seed,
> связан с тринадцатью внешними кластерами, имеет пять отправителей и
> девяносто девять получателей. Это соответствует правилу coordinator;
> distributor тоже остаётся видимой альтернативой. Приоритет почти единица,
> но это балл очередности проверки, а не вероятность нарушения.
>
> Второй пример — возможный транзит: вход 160 тысяч тенге, выход 156 тысяч.
> Отношение 0,975 попадает в наш интервал 0,8–1,2. Это сходство сумм;
> движение именно тех же денег требует проверки дат переводов.
>
> Третий клиент получил 555 тысяч от трёх отправителей, а исходящих не видно.
> Он находится на четвёртом колене, где сбор исходящих оборван. Поэтому ядро
> показывает гипотезу сборщика со сниженной силой признаков. Для проверки
> дальнейшей роли аналитику нужны исходящие переводы.
>
> Пороги и веса открыты, у каждого результата есть объяснение и ограничения.
> Общий прогон сохраняет всех 2248 клиентов, включая 19 изолированных seed.

## Что открыть во время выступления

В готовом интерфейсе: найти точный gid → открыть карточку → показать роль,
объяснение, вклад в приоритет и предупреждения. До появления UI те же поля
доступны в `out/graph.json` и `out/result.json`.

| Порядок | gid для копирования | Роль | role_score | priority_score |
|---|---|---|---:|---:|
| 1 | `100000000331309100` | coordinator | 1.00000 | 0.99982 |
| 2 | `100000008692291100` | transit | 0.88008 | 0.84399 |
| 3 | `100000003037476100` | consolidator | 0.69014 | 0.84069 |
| Запасной | `100000000456947100` | peripheral | 0.00000 | 0.00000 |

Gid — строка, при копировании не преобразовывать его в JavaScript Number.
Это выбранные примеры для защиты; в алгоритме нет правил для конкретных gid.

## Разбор, если жюри просит показать расчёт

Обозначения: S — число разных seed, из которых узел достижим по направлению
переводов; B — число внешних кластеров непосредственных контрагентов;
I/O — наблюдаемые суммы входящих/исходящих; P — число уникальных контрагентов.
Переводы самому себе исключены из этих признаков. Seed не считает себя.

`Q(X)` — доля положительных значений признака во всём графе, которые <= X.
Для нуля Q=0. `sat(x,t)=min(1,x/t)`.

```text
priority = 0.35*sat(S,5) + 0.30*Q(max(I,O))
         + 0.20*Q(P)    + 0.15*sat(B,3)
```

| Вклад | Координирующий | Транзит | Сборщик depth=4 |
|---|---:|---:|---:|
| Охват seed | 0.35000 | 0.35000 | 0.35000 |
| Объём | 0.30000 | 0.20565 | 0.26743 |
| Контрагенты | 0.19982 | 0.18834 | 0.17326 |
| Внешние кластеры | 0.15000 | 0.10000 | 0.05000 |
| Итого | **0.99982** | **0.84399** | **0.84069** |

### 1. Почему coordinator

- S=7 при пороге 3; B=13 при пороге 2.
- Отправителей 5 и получателей 99: оба числа >=2.
- `Q(max(I,O))=1`, порог 0.75. Все условия выполнены.
- `role_score = 0.5 + 0.2*sat(7,6) + 0.15*sat(13,4) + 0.15*1 = 1`.
- Подходит и distributor. Правила проверяются в опубликованном порядке:
  coordinator → consolidator → distributor → transit → terminal → peripheral.
  Основная роль — первая подходящая, альтернативы есть в `role_candidates`.

Наблюдаемый вход 984635 KZT, выход 23001375 KZT. Превышение исходящих над
входящими не позволяет вычислить баланс или источник денег: неизвестны
начальный остаток и операции за пределами выгрузки.

Действие аналитика: проверить связи с несколькими исходными seed и участниками
других кластеров, затем сопоставить последовательность переводов.
Достижимость не доказывает управление участниками или происхождение денег.

### 2. Почему transit

- Клиент не seed, depth=3; по три отправителя и получателя.
- `O/I = 156000/160000 = 0.975`, допустимый интервал 0.8–1.2.
- Coordinator не проходит: перцентиль объёма 0.68551 < 0.75.
- Consolidator не проходит: отправителей не больше получателей.
- Distributor не проходит: получателей меньше пяти.
- Близость сумм `C = 1 - abs(0.975-1)/0.2 = 0.875`.
- `min(Q(I),Q(O)) = 0.5878962536`.
- `role_score = 0.5 + 0.3*0.875 + 0.2*0.5878962536 ≈ 0.8800792507`.

Действие аналитика: сопоставить время входящих и исходящих в transactions.
Текущая C++-версия использует агрегаты и не выполняет временное сопоставление.
В коротком evidence отношение показано с двумя знаками; точное значение 0.975
доступно в `features.observed_pass_through`.

### 3. Почему сборщик на границе

- Depth=4; три отправителя, ноль видимых получателей, вход 555000 KZT.
- `Q(I)=0.9383499547 >= 0.5`: правило consolidator выполнено.
- Базовая сила: `0.55 + 0.25*sat(3,6) + 0.2*0.9383499547 ≈ 0.8626699909`.
- Множитель границы: `0.8626699909*0.8 ≈ 0.6901359927`.
- На depth=4 правила terminal и transit отключены. В карточке обязательно
  `OUTGOING_INCOMPLETE_AT_DEPTH_LIMIT`.

Действие аналитика: получить продолжение исходящих переводов за границей обхода.
Сила роли снижена, а приоритет 0.84069 остаётся высоким: это разные показатели,
и неполнота данных сама по себе не повод отложить проверку.

### Запасной: seed без связей

`100000000456947100`: depth=0, нет наблюдаемых рёбер, роль peripheral и оба
балла равны нулю. Предупреждения: `NO_OBSERVED_EDGES`, `SEED_INCOMING_INCOMPLETE`.
Он сохраняется в данных и должен находиться поиском. Нулевой графовый балл
означает отсутствие сигналов выбранных правил; причины включения клиента
в исходный список seed могут находиться вне этой выгрузки.

## Короткие ответы жюри

| Вопрос | Ответ |
|---|---|
| Вы нашли организатора группы? | Выделили кандидата на структурно связующую роль. Для вывода о реальных отношениях нужны дополнительные данные и проверка аналитика. |
| Score 1 — это 100%? | Это максимальная сила выбранного правила. `priority_score` отдельно задаёт порядок проверки. Ни один балл не откалиброван как вероятность. |
| Откуда пороги и веса? | Это явно заданные эвристики прототипа. Они доступны в JSON и сохраняются в результате. Для настройки по качеству нужна экспертная разметка. |
| Почему без исходящих не terminal? | На четвёртом колене исходящие не собраны; у seed неполны входящие. Поэтому terminal и transit для этих случаев запрещены. |
| Почему выбран coordinator, если есть distributor? | Срабатывают оба правила; coordinator имеет более раннее место в документированном порядке. Альтернативная роль сохраняется. |
| Где AI и какая точность? | Сейчас это интерпретируемая система правил и графовая кластеризация. Обученной модели и размеченного эталона нет; accuracy мы не заявляем. Тесты проверяют реализацию и контракт. |
| Почему C++? | Это наш отдельный модуль графовых обходов и правил с простым JSON-контрактом. Python отвечает за загрузку, метрики и кластеры. Преимущество в скорости над Python мы отдельно не измеряли. |
| Как вычисляется достижимость? | По одному BFS по направленным рёбрам из каждого seed. Один seed учитывается один раз, циклы не увеличивают счётчик, сам seed себя не учитывает. |
| Как масштабируется? | Фаза достижимости — O(K*(N+M)), где K — число seed. Граф хранится в O(N+M); JSON также загружается в память. Проверенный объём — 2248 узлов и 3119 рёбер. |
| Кластер означает преступную группу? | Louvain выделяет сообщества по структуре и весам переводов. Их интерпретация — отдельная проверка; алгоритм не устанавливает характер отношений. |
| У графа точно сохранено направление? | Для C++-обходов и потоков — да. Для Louvain Python строит отдельную ненаправленную проекцию с суммой встречных весов. Исходный направленный граф сохраняется. |
| Почему не только PageRank? | Python передаёт PageRank, но текущий приоритет использует четыре явно объяснимых сигнала: охват seed, объём, контрагентов и внешние кластеры. |
