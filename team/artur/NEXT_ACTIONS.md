# Передача следующей доработки Артура — C++ 1.2.0

Реализовано поле `nodes[].next_actions: string[]` в `result.json`.
Источник контракта: [engine/CONTRACT.md](../../engine/CONTRACT.md), раздел
«Следующие действия: дополнение 1.2.0»; правила — [engine/README.md](../../engine/README.md).

- Всегда 1–3 уникальные непустые строки, каждая <=200 Unicode-символов.
- Сначала полнота наблюдений, затем действие основной роли. Граница и seed
  учитываются независимо; действия относятся к гипотезе и не являются обвинением.
- Вход, CLI, schema_version=1.0, формулы, оценки и CSV сохраняются.
- Поле необязательно для старых результатов; ядро 1.2.0 выдаёт его всем узлам.

## Арман

1. Собрать ядро 1.2.0: `powershell -ExecutionPolicy Bypass -File engine/build.ps1`.
2. Передача через `hackalem/protocol.py:validate_result` уже добавлена: присутствующее
   `next_actions` сохраняется. Schema в engine описывает и проверяет новое поле.
3. Проверить равенство списков в result.json и graph.json по всем gid. Три CSV
   сохраняют фиксированные колонки из ТЗ.
4. После интеграции пересчитать полный комплект через `python prepare_ui_data.py`,
   проверить его и отправить все изменившиеся файлы комплекта вместе.
5. В старых результатах отсутствие поля допустимо. При проверке нового комплекта
   контролировать сохранение списков и совместимость старого пакета.

## Савелий

Читать необязательное поле `next_actions` в узле graph.json. Вывести список
«Что проверить дальше» в исходном порядке, скрыть блок при отсутствии поля.
Тексты не вычислять из role в UI. Контрольные случаи после пересчёта:

| gid | Ожидаемый смысл действий |
|---|---|
| 100000000331309100 | Маршруты от 7 seed и связи с 13 внешними кластерами |
| 100000008692291100 | Даты входящих/исходящих, порядок и интервалы |
| 100000003037476100 | Продолжение исходящих depth=4 + источники от 3 отправителей |
| 100000000456947100 | Полнота отсутствующих операций + недостающие входящие seed |

gid в таблице — примеры для приёмки текущего датасета; в правилах ядра gid нет.
Наличие поля в C++ и его передача через Python не меняют старый graph.json:
нужен новый полный расчёт, затем проверка UI. Поставку frontend/public/data
Артур в этом изменении не пересчитывал; её готовит Арман.
