## 1. Подтвердить финальный запуск — начать параллельно

**Арман, 20–30 минут.** Новая копия последнего main на своём ноутбуке:
установка по README → сборка ядра → `python prepare_ui_data.py` →
`python verify_outputs.py` → `npm ci`, `npm test`, `npm run build`, запуск UI.
Зафиксировать commit, ОС, команды, результат и wall time.

**Критерий готовности:** без правки исходников получены 2248 ролей, 88 кластеров,
топ-20; проверка пакета проходит, пересчёт <300 секунд, интерфейс открывается.
Если такой запуск уже выполнен на точной финальной версии, достаточно записать
его фактические результаты и повторить затронутые проверки после изменений.

**Савелий + Артур, 10 минут:** в обычном браузере повторить четыре контрольных
случая и три произвольных gid; скачать все три CSV и сверить их с открытым
комплектом. Отдельно проверить экспорт после пересчёта без обновления страницы:
скачиваются файлы прежнего открытого расчёта; после «Обновить файлы» — нового.
Автоматические тесты покрывают эту смену; сохранение файлов проверить вручную
на браузере демонстрационного ноутбука.

## 2. Усилить действие аналитика — приоритетная доработка

**Статус:** часть Артура выполнена в C++ 1.2.0, 34 теста проходят; на полном
датасете действия добавлены всем 2248 узлам без изменения прежних результатов.
[Зафиксированный контракт и передача](artur/NEXT_ACTIONS.md). Минимальная передача
через Python включена и проверена. Следующие шаги — пересчёт пакета Арманом
и показ Савелием; текущий готовый пакет 1.1.0 ещё без поля.

**Артур — правила и C++ (30–40 минут).** Добавить для произвольного клиента
объяснимый список следующих действий по уже имеющимся признакам:

| Условие | Действие аналитика |
|---|---|
| Изолированный клиент | Проверить полноту выгрузки, период и порог; запросить дополнительные операции |
| depth=4 | Запросить продолжение исходящих переводов за границей обхода |
| is_seed | Запросить входящие, не попавшие в выборку исходящих переводов |
| transit | Сопоставить даты входящих и исходящих; проверить порядок и интервалы |
| coordinator | Проверить маршруты от разных seed и связи между сообществами |
| consolidator / distributor | Проверить источники поступлений / дальнейших получателей по наблюдаемому направлению |
| terminal | Проверить исходящие за пределами периода, порога и банка |

Зафиксированный совместимый контракт: необязательное `next_actions: string[]`
в результате узла; ядро 1.2.0 всегда выдаёт 1–3 строки до 200 символов. Сформировать сообщения
из условий, задокументировать порядок и проверить совмещение нескольких
ограничений. Каждый текст должен следовать из данных; конкретные gid в правилах
не используются. Поле уже есть в C++ и новом Python-экспорте; публикация
пересчитанного комплекта и отображение в UI ещё не завершены.

**Арман — полный пакет (15–20 минут параллельно).** Контракт, schema и минимальная
передача через validate_result уже обновлены. Пересчитать пакет и проверить
отсутствие потерь next_actions между result.json и graph.json. Три обязательных CSV сохраняют
фиксированные колонки из ТЗ.

**Савелий — показ (15–20 минут после контракта).** Вывести «Что проверить дальше»
в карточке; старый пакет без поля должен по-прежнему загружаться.

**Готово, если:** четыре контрольных случая получают корректные действия,
граничному узлу предлагается продолжить наблюдение, seed не трактуется через
полный баланс. Это опциональная «оценка полноты» из ТЗ и конкретное усиление
ценности/качества: пользователь получает следующий шаг, который можно выполнить.

## 3. Сделать денежную связь проверяемой на экране

**Савелий, 30–40 минут параллельно с п. 2.** При выборе ребра показать:
полные строковые `src → dst`, `sum_kzt`, `n_tx` из JSON. Сохранять направление
и различать встречные переводы. Сумма может управлять толщиной линии, но числовая
подпись или карточка выбранной связи важнее декоративного изменения.

**Готово, если:** у выбранной связи читаются оба клиента, сумма и количество;
значения совпадают с edges, фильтры не превращают одну связь в другую.
Сейчас стрелки уже есть; точные веса отдельных связей на экране не показаны.
