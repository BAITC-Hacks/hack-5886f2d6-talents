# Контракт структурного эксперимента v1 — C++ 1.3.0

**Статус: реализовано в C++ 1.3.0; полный расчёт и независимая сверка пройдены.
UI Савелия подключён; пакет frontend/public/data 1.2.0 ожидает пересчёта Арманом
и совместной приёмки на данных 1.3.0.**
Результаты сравнения стратегий: [EVIDENCE.md](../docs/EVIDENCE.md).
Поле необязательно: `result.json.meta.resilience` → `graph.json.meta.resilience`.
Python уже копирует engine meta в graph meta и в meta.engine_meta. CSV,
schema_version=1.0, вход ядра, оценки и роли остаются прежними.

```text
resilience: {
  schema_version: "1.0",
  connectivity: "weak",
  scope: "observed_graph",
  baseline: Scenario,
  scenarios: Scenario[]
}

Scenario: {
  strategy: "baseline" | "priority" | "volume",
  requested_k: integer >= 0,
  removed_gids: string[],
  remaining_nodes: integer >= 0,
  remaining_edges: integer >= 0,
  weak_components: integer >= 0,
  isolated_nodes: integer >= 0,
  largest_component_nodes: integer >= 0,
  largest_component_share_remaining: number in [0,1],
  removed_edge_sum_kzt: number >= 0,
  removed_edge_sum_share: number in [0,1]
}
```

## Выбор клиентов и порядок

- baseline: strategy=baseline, requested_k=0, removed_gids=[]; полный исходный граф.
- scenarios: сначала priority с k=1,3,5,10, затем volume с k=1,3,5,10 — 8 записей.
- priority: по убыванию **неокруглённого** priority_score, затем числового gid.
- volume: по убыванию `max(observed_in_kzt, observed_out_kzt)` без переводов себе,
  затем числового gid. Значения уже рассчитаны C++.
- Убираются первые min(requested_k,N) клиентов и все инцидентные рёбра.
  `removed_gids` — в порядке отбора. На графе с N<k не создавать фиктивные gid.
- Все сценарии независимы: каждый начинается с полного исходного графа.
  Роли, кластеры, приоритеты после исключения не пересчитываются.

## Точный смысл показателей

- Граф переводов остаётся направленным. **Слабая связность** при подсчёте
  компонент игнорирует направление, что явно указывается в UI и документации.
- Компоненты включают все оставшиеся вершины, включая изолированные.
  Для пустого графа weak_components=0 и largest_component_nodes=0.
- `isolated_nodes`: оставшиеся вершины **без внешних контрагентов**, петля
  не делает клиента связанным с другими. Входящая или исходящая связь с другим
  оставшимся клиентом исключает из изолированных.
- `remaining_edges`: число исходных направленных рёбер, у которых остались
  оба конца. Встречные рёбра различаются, петли входят в счётчик.
- `largest_component_share_remaining` = largest_component_nodes / remaining_nodes;
  при remaining_nodes=0 это 0. UI подписывает «доля среди оставшихся» и показывает
  абсолютные числа. Одна эта доля не является мерой улучшения или распада.
- `removed_edge_sum_kzt`: сумма исходных sum_kzt всех рёбер, у которых исключён
  хотя бы один конец. Каждое ребро учитывается ровно один раз, включая петли;
  встречные направления не взаимозачитываются.
- `removed_edge_sum_share`: эта сумма / сумма sum_kzt всех исходных рёбер;
  при нулевой общей сумме — 0. У baseline обе величины равны 0.
- Все числа конечны. Не допускать NaN/Infinity и выхода долей за [0,1]
  из-за накопления погрешности. gid всегда строка; числа сравниваются по int64.

## Показ в интерфейсе

Заголовок «Устойчивость наблюдаемой сети», выбор способа и N. Показывать baseline
и выбранный сценарий: крупнейшая компонента (число клиентов), слабые компоненты,
изолированные, оставшиеся клиенты/связи, сумма/доля оборота исчезнувших связей.
Перечень removed_gids ведёт в существующие карточки исходного графа.
Фактическое число исключённых клиентов показывается как removed_gids.length:
при малом графе оно может быть меньше выбранного N. Изменение долей называть
процентными пунктами, если показывается их разность; абсолютные размеры обязательны.
Исключение симулируется; реальные данные и существующий граф не удаляются.
Старый graph.json без поля работает, блок скрыт. Некорректное присутствующее
поле выдаёт понятную ошибку формата, а не фиктивные нули.

Обязательная оговорка: «Структурный эксперимент на неполной наблюдаемой сети.
Он не доказывает прекращение переводов или деятельности группы. Удалённый
оборот — прошлые наблюдаемые операции, не предотвращённые потери».

## Приёмка

- Цепь с удалением середины, звезда с удалением центра, цикл, две компоненты,
  изолированный seed, только петля, встречные рёбра, пустой и полностью удалённый граф.
- Связь между двумя исключёнными узлами суммируется один раз.
- Равные баллы/объёмы сортируются по числовому gid, перестановка входа ничего не меняет.
- Крупнейшая компонента в абсолютных узлах и remaining_edges не растут при
  наращивании k одной стратегии. weak_components и isolated_nodes могут уменьшаться:
  удаляется целая компонента или изолированная вершина.
- Арман независимо сверяет все сценарии с NetworkX и исходными рёбрами;
  результат C++/graph совпадает. Обязательные CSV не изменились.
- Добавленный расчёт — O(N log N + 9(N+M)), без нового BFS от каждого seed.
