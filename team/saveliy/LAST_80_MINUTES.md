# Савелий — экран структурного эксперимента и проверка удобства

Проверка по Word принята. Следующий блок закончить до 17:10; интеграция —
17:10–17:25; с 17:25 только исправления. Источник имён и типов:
[RESILIENCE_CONTRACT.md](../RESILIENCE_CONTRACT.md).

## 1. Устойчивость наблюдаемой сети

Добавить небольшой блок рядом с обзором/топом. Выбор N=1/3/5/10 и способа
«По приоритету» / «По объёму переводов». Показать baseline и выбранный сценарий:
крупнейшая компонента (узлы), слабые компоненты, изолированные, оставшиеся
клиенты/связи и сумма/доля прошлых операций на исключённых связях. Перечень
removed_gids открывает уже существующую карточку клиента.

Источник — graph.meta.resilience. Сейчас parseGraph оставляет только несколько
meta-полей: расширь типы/парсер, чтобы новый блок сохранился. Без поля старый
пакет работает и блок скрыт. С некорректным полем — понятная ошибка формата.
Все вычисления приходят из C++; UI только отображает готовые сценарии.
Можно начать с синтетических test fixtures; рабочий экран ждёт полный пакет Армана.

Обязательно показать оговорку из контракта. Подпись доли крупнейшей компоненты —
«среди оставшихся клиентов»; рядом абсолютный размер. Сумма исчезнувших рёбер
не называется предотвращённым ущербом. Исходный граф и файлы не удаляются.
Не заявлять превосходство priority над volume, если фактические числа этого не показывают.

## 2. Приёмка после получения пакета

Все 8 сочетаний, переход из удалённого gid в карточку, возврат к исходному графу,
старый пакет без поля, пустая/полностью удалённая модель и новый hash-пакет.
Затем 3 скачивания, поиск 3 произвольных gid, npm test/build, console без ошибок.
Не повторять полностью уже закрытый Word-аудит: проверить новый блок и затронутые сценарии.

## 3. Измерение пользовательского сценария, 10 минут

После 17:25 дать одному тиммейту (не автору UI) три задания: найти заданный gid;
назвать причину приоритета и ограничение; открыть связь и сохранить CSV.
Записать фактическое время и результат в team/USABILITY_CHECK.md, указав
внутреннего участника и его знакомство с проектом. Без выдуманных замеров,
без заявления экономии времени AML-аналитика. Если нужен ответ человека,
задай ему задания и дождись; автоматический прогон не выдавай за пользовательский.

Обнови 5-минутное демо одним коротким сравнением before/after, сохранив живой
пересчёт и 2–3 узла. Мои файлы: frontend/src, frontend tests/docs, team/USABILITY_CHECK.md.
Полный public/data публикует Арман; ядро и Python не редактировать.
