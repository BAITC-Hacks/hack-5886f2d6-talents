## Что уже готово

C++-ядро Артура выдаёт роли, оценки, объяснения, топ-20, ограничения данных
и следующие действия next_actions.
Арман объединяет это с исходными метриками и рёбрами в graph.json.
Пересчитывать аналитику на фронтенде не нужно.

Для начала работы используй [graph.example.json](graph.example.json). Это
демонстрационный граф из 4 узлов с результатами настоящего C++-ядра 1.1.0; поле
`meta.is_demo=true` обозначает учебный пример. Числа и гипотезы в нём не являются
выводами о полном датасете. Кластеры примера рассчитаны Python на синтетических данных.
Файл совпадает с `examples/graph.json`, который создаётся командой
`python make_examples.py --core engine/build/engine.exe`.

Формат graph.json ниже реализован в Python и согласован с корневым CONTRACT.md.
Действующий контракт C++ описан отдельно в
[engine/CONTRACT.md](../../engine/CONTRACT.md).

## Один экран для демо

1. Топ минимум из 20 клиентов на полном датасете. Клик выбирает клиента на графе.
2. Граф с направлением переводов и переключением раскраски: роль / кластер.
3. Поиск по точному gid, включая изолированные узлы и узлы вне текущего фильтра.
   При нахождении раскрыть нужный кластер или окружение.
4. Фильтры роли и кластера, сброс фильтров.
5. Карточка клиента: gid, роль, сила признаков, приоритет, evidence, суммы,
   число контрагентов, принадлежность к seed, глубина и предупреждения.
6. Раскрываемый блок с `priority_breakdown`, показывающий причины приоритета.
7. Скачивание трёх CSV открытого проверенного расчёта.
8. Карточка выбранной направленной связи: полные src→dst, сумма и число переводов.
9. «Что проверить дальше» — действия аналитика из next_actions ядра.

Для читаемости сначала показывай выбранный кластер или окружение клиента.
Скрытая фильтром связь не означает отсутствующую связь: в карточке показывай
полные метрики узла из данных. Сохраняй направление стрелок и различимость
встречных переводов. Изолированный узел должен отображаться при поиске.

## Согласованный graph.json

```text
schema_version: "1.0"
nodes: массив объединённых исходных метрик и результатов C++
edges: массив {id, src, dst, sum_kzt, n_tx, ...}
top_nodes: массив {rank, gid, role, priority_score, why}
clusters: массив {cluster_id, n_nodes, n_seed, sum_kzt_internal, top_gids, hypothesis}
meta: сведения о расчёте, включая is_demo
```

Каждый узел:

```text
gid: string
cluster_id: integer
depth: integer
is_seed: boolean
in_deg, out_deg, in_tx, out_tx: integer
in_kzt, out_kzt, pagerank: number
pass_through: number | null (необязательно)
role: одна из шести ролей
role_score, priority_score: number от 0 до 1
evidence, why: string
features: дополнительные признаки
role_candidates: массив {role, score}
priority_breakdown: объект с четырьмя компонентами
warnings: массив кодов ограничений
next_actions?: string[] — следующие действия из ядра в исходном порядке, необязательное поле
```

Ядро 1.2.0 передаёт 1–3 уникальных непустых next_actions, каждое до 200
Unicode-символов. Если в старом пакете поля нет или список пуст, UI скрывает блок.
Подробности — [контракт ядра](../../engine/CONTRACT.md).

Важные `features`: seed_reach_count, direct_seed_senders, min_seed_hops (может
быть null), external_cluster_count, counterparty_count, boundary_node,
truncated_by_depth, observed_in_kzt, observed_out_kzt, observed_pass_through.
`observed_*` исключают переводы самому себе. Исходные in_kzt/out_kzt сохраняют
метрики стартера. Подписывай различие, если показываешь оба набора.

Все идентификаторы — строки. Не использовать `Number(gid)` или `parseInt(gid)`:
в датасете встречаются значения больше безопасного диапазона JavaScript.
Для сравнений достаточно строкового равенства; порядок топа уже подготовлен
пайплайном. Если нужна числовая сортировка gid, использовать BigInt.

Отображение через Cytoscape.js:

```typescript
const elements = [
  ...graph.nodes.map(node => ({
    data: { ...node, id: node.gid, label: node.gid }
  })),
  ...graph.edges.map(edge => ({
    data: {
      ...edge,
      id: `edge:${edge.id}`,
      source: edge.src,
      target: edge.dst
    }
  }))
];
```

Базовый JSON не зависит от Cytoscape: преобразование выполняет интерфейс.
Арман сохраняет graph.json и CSV в согласованный с тобой каталог, например
`frontend/public/data/`. До интеграции можно скопировать graph.example.json
в свой public/data/graph.json. Не пытайся скачивать CSV из учебного примера:
их там нет, кнопки подключаются после передачи файлов Арманом.

## Подписи ролей

| Код | Подпись |
|---|---|
| consolidator | Признаки консолидации |
| transit | Признаки транзита |
| distributor | Признаки распределения |
| terminal | Возможный конечный получатель |
| coordinator | Кандидат на координирующую роль |
| peripheral | Недостаточно признаков роли |

`role_score` подписать «Сила признаков роли», `priority_score` — «Приоритет
проверки». Не подписывать их «Вероятность преступления» или «Точность».
`evidence` объясняет роль, `why` объясняет приоритет. Не округлять исходные
значения перед сортировкой; округление нужно только для отображения.

## Переводы предупреждений

| Код | Текст для пользователя |
|---|---|
| OBSERVED_SUBGRAPH_ONLY | Видна только часть переводов за выбранный период |
| ROLE_IS_HYPOTHESIS | Роль — гипотеза для проверки |
| OUTGOING_INCOMPLETE_AT_DEPTH_LIMIT | Граница обхода: дальнейшие исходящие переводы могут быть не видны |
| SEED_INCOMING_INCOMPLETE | Для исходного клиента входящие переводы представлены неполно |
| NO_OBSERVED_EDGES | В выгрузке нет связей этого клиента |
| SELF_TRANSFERS_EXCLUDED_FROM_ROLE_AND_PRIORITY | Переводы самому себе исключены из оценки роли и приоритета |
| OBSERVED_OUTFLOW_EXCEEDS_INFLOW | Видимые исходящие превышают входящие; это не полный баланс счёта |

Общие предупреждения можно показать один раз над графом, специфические — в карточке.
Для null отображать «Нет данных», не 0. Для неизвестного кода оставить нейтральное
сообщение о дополнительном ограничении данных.

## Что проверить перед защитой

- Загрузка полного graph.json; понятные состояния загрузки, ошибки и пустого поиска.
- Выбор узла из топа и поиск произвольного gid.
- Изолированный клиент и клиент depth=4.
- Стрелки направления, видимые цвета ролей и кластеров, работа фильтров.
- Суммы и объяснения соответствуют выбранному узлу, все gid сохранены точно.
- Действия next_actions совпадают с JSON и отображаются в переданном порядке.
- Карточка связи сохраняет направление и отдельные числа встречных переводов.
- На полном датасете топ содержит минимум 20 узлов и скачиваются три CSV.
