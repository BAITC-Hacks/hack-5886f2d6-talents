# Следующие задачи команды

Состояние после загрузки Python-коммита `ad6b1d5` и совмещения с C++ 1.1.0:
аналитический пайплайн работает целиком. На полном датасете получены 2248 узлов,
3119 рёбер, 88 кластеров, топ-20 и три CSV. Полный проверенный запуск — 3.114 секунды.
Прошли 49 Python-тестов и 28 тестов ядра. Дополнительные признаки, альтернативные
роли, предупреждения и конфигурация доходят до graph.json без потерь.

Следующий основной результат — рабочий экран Савелия на реальных данных.
В загруженном состоянии репозитория исходников интерфейса пока нет.

## Артур — аналитическая часть и защита

1. Зафиксировать и передать команде согласованную версию C++ 1.1.0 с обновлёнными
   примерами и документацией. Сохранить текущие поля контракта при подключении UI.
2. Подготовить устное объяснение трёх случаев из [DEMO_CASES.md](DEMO_CASES.md):
   координирующий узел, транзит, сборщик на границе обхода. Для каждого показать
   сработавшее правило, фактические числа, вклад в приоритет и ограничение вывода.
3. Вместе с Савелием проверить карточки этих узлов: роль, evidence, why,
   role_candidates, warnings и priority_breakdown должны совпадать с graph.json.
4. Подготовить короткий ответ на вопросы жюри: почему coordinator не означает
   доказанного организатора, почему высокий score не является вероятностью,
   почему узел depth=4 не объявляется terminal и почему изолированные seed сохранены.
5. После первого готового UI выбрать запасной узел для проверки произвольного gid
   и помочь Арману сверить демонстрационные CSV с тем же самым прогоном.

Результат Артура: стабильное ядро, проверенные карточки и возможность за минуту
объяснить любой выбранный узел через правила, конфигурацию и метрики.

## Арман — доставка данных в UI и воспроизводимость

1. Согласовать с Савелием путь статических данных. Предлагаемые URL:
   `/data/graph.json`, `/data/nodes_roles.csv`, `/data/clusters.csv`, `/data/top_nodes.csv`.
2. Подключить существующий пайплайн к каталогу UI. Если проект Савелия находится
   в `frontend/`, уже работает команда:

   ```sh
   python pipeline.py --out frontend/public/data
   ```

   Если папка другая, заменить только путь `--out`. Отдельный сервер для выдачи
   рассчитанного JSON текущему прототипу не требуется.
3. Проверить запуск на втором ноутбуке по README: установка зависимостей,
   Release-сборка C++, затем одна команда пересчёта. Добавить фактическую команду
   запуска интерфейса после первого коммита Савелия.
4. Сохранить финальный набор из одного успешного прогона: три CSV, graph.json,
   validation.json и run_manifest.json. Проверить хэши и `meta.is_demo=false`.
5. Подготовить раздел защиты о данных и кластерах: 81 seed, четыре колена,
   ограничения выборки, 19 изолированных узлов, Louvain и смысл внутренних сумм.

Результат Армана: UI получает настоящий датасет, все выгрузки скачиваются,
проект воспроизводится на другом ноутбуке по инструкции.

## Савелий — завершить обязательный экран

Первый следующий коммит: запускаемый интерфейс, чтение graph.json, таблица топ-20
и карточка выбранного клиента. Можно начинать с `examples/graph.json`, затем
переключить тот же код на полный файл из пайплайна.

Далее по порядку:

1. Направленный граф: стрелки переводов, раскраска по роли или кластеру,
   выбор узла и отображение его окружения.
2. Поиск по точному строковому gid. Должен находить узел за пределами текущего
   фильтра и изолированного клиента; после поиска раскрывать нужное окружение.
3. Фильтры роли и кластера, сброс фильтров. Отображать выбранное сообщество или
   локальное окружение, чтобы весь граф не превращался в нечитаемое скопление.
4. В карточке обязательно показать evidence и ограничения наблюдения. Детали
   priority_breakdown и альтернативные роли можно раскрывать отдельным блоком.
   role_score подписать «Сила признаков роли», priority_score — «Приоритет проверки».
5. Подключить скачивание трёх CSV, состояния загрузки/ошибки/пустого поиска,
   проверить большой gid без преобразования в JavaScript Number.
6. Отправить первый рабочий экран в общий репозиторий, затем вместе с Артуром
   пройти [DEMO_CASES.md](DEMO_CASES.md) на настоящих данных.

Результат Савелия: по названному жюри gid команда находит клиента, показывает
направление переводов, роль, обоснование, кластер и экспортирует результаты.

## Общая приёмка перед сдачей

- Арман запускает расчёт с настоящим C++ и получает один согласованный комплект файлов.
- Савелий загружает этот graph.json; поиск работает для лидера, транзита,
  depth=4 и изолированного seed.
- Артур сверяет показанные значения с result.json и объясняет критерии.
- На экране видны направления, роли и кластеры; скачиваются три CSV.
- README описывает фактическую сборку, расчёт и запуск интерфейса; диаграмма
  архитектуры в README соответствует показанному решению.
- Команда репетирует пятиминутное демо на одном ноутбуке без обязательных
  внешних сервисов. Последнюю версию кода и данных фиксирует перед защитой.

Сценарий демо: Арман показывает запуск и входные ограничения; Савелий — граф,
топ и поиск; Артур — три объяснимых случая; в завершение — скачивание CSV и
действие аналитика по узлу на границе наблюдений.
