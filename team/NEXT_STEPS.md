## Арман — финальный комплект и второй ноутбук

Действующий путь передачи — `frontend/public/data/`; его использует UI.
Настоящий полный набор C++ 1.1.0 включён в Git. Пересчёт и проверка —
`python prepare_ui_data.py`, проверка без пересчёта — `python verify_outputs.py`.
URL и команды: [frontend/README.md](../frontend/README.md).
Материалы выступления: [DATA_AND_CLUSTERS.md](arman/DATA_AND_CLUSTERS.md).
Проверка в отдельной чистой среде на этом же компьютере:
[REPRODUCIBILITY.md](arman/REPRODUCIBILITY.md).

1. На втором ноутбуке повторить установку зависимостей, Release-сборку C++,
   полный пересчёт и запуск интерфейса по README. Зафиксировать ОС и результат;
   пока такой запуск не подтверждён.
2. При изменении расчёта обновлять весь комплект одним запуском:

   ```sh
   python prepare_ui_data.py
   python verify_outputs.py
   ```

   В `frontend/public/data/` сохраняются три CSV, graph.json, validation.json,
   run_manifest.json и input/result для независимой сверки. Проверять хэши
   и `meta.is_demo=false`, использовать эти же файлы в UI.
3. Перед сдачей вместе с Савелием сверить загрузку JSON и скачивание CSV из одного
   прогона. Наличие файлов по HTTP само по себе не заменяет проверку экрана.
4. Для защиты сверить раздел о данных и кластерах: 81 seed, четыре колена,
   19 изолированных узлов, Louvain, внутренние суммы и ограничения выборки.

Результат Армана: согласованный финальный комплект и подтверждённый запуск
на втором ноутбуке.

## Савелий — приёмка готового экрана

Интерфейс реализован на React, Vite, TypeScript и Cytoscape.js. Из корня:

```sh
cd frontend
npm ci
npm run dev
```

1. Вместе с командой повторить топ → выбор клиента → направленные связи →
   карточка → экспорт на финальной версии.
2. Пройти четыре [контрольных случая](DEMO_CASES.md), включая точный строковый
   gid вне фильтра, изолированного клиента и depth=4.
3. Проверить раскраску по роли/кластеру, фильтры и понятность локального окружения.
   Карточка показывает полные метрики узла независимо от скрытых связей.
4. Сверить evidence, why, детализацию приоритета, альтернативные роли и ограничения.
   role_score — «Сила признаков роли», priority_score — «Приоритет проверки».
5. Повторить скачивание трёх CSV и пятиминутное демо:
   [frontend/DEMO.md](../frontend/DEMO.md). Зафиксировать код и данные перед сдачей.

Результат Савелия: по названному жюри gid команда находит клиента, показывает
направление переводов, роль, обоснование, кластер и экспортирует результаты.

## Общая приёмка перед сдачей

- Арман подтверждает один согласованный комплект финального прогона с настоящим C++.
- Савелий показывает поиск лидера, транзита, depth=4 и изолированного seed.
- Артур сверяет показанные значения с result.json и объясняет критерии.
- На экране видны направления, роли и кластеры; скачиваются три CSV.
- Команда повторяет запуск на втором ноутбуке и фиксирует фактический результат.
- README соответствует сборке, расчёту и запуску; схема архитектуры соответствует решению.
- Команда репетирует пятиминутное демо без обязательных внешних сервисов.
  Последнюю версию кода и данных фиксирует перед защитой.

Сценарий демо: Арман показывает запуск и входные ограничения; Савелий — граф,
топ и поиск; Артур — три объяснимых случая; в завершение — скачивание CSV и
действие аналитика по узлу на границе наблюдений.
